SECURITY AND PRIVACY

The app uses local system display APIs. It has no network client/server,
accounts, analytics, credential storage or third-party runtime dependencies.
Settings, including any coordinates entered by the user, stay in local
preferences. The recovery helper runs with the same user privileges as the app
and accepts a bounded binary protocol on a private standard-input pipe.
Mouse event monitors are enabled only while the quick panel is open, to
dismiss it on an outside click. They do not record or transmit input.

PRE-PUBLICATION CHECKS
Gitleaks 8.30.1: scanned staged contents and the complete initial Git history
with its standard rules and without comment-based secret exceptions.
Apple Clang 21 Static Analyzer: core, unix and security checkers, covering
both C files, including the recovery protocol and allocation/free paths.
AddressSanitizer and UndefinedBehaviorSanitizer: 116 bounded/truncated helper
input cases, with no display writes during those protocol tests.
Swift compiler: type checking with warnings treated as errors.
Core tests: 31 color, scheduling, settings and screen-placement checks.
Manual review: Swift process launching, executable paths, local preferences,
file access, event monitors, display restoration and publication contents.
Privacy review: no personal names, email addresses, home-directory paths,
local preferences, personal logs, screenshots, credentials or signing keys
in the publication payload. Commit metadata uses a generic project identity.

No findings were detected by those automated checks. This is a scoped local
review, not a guarantee that the software is free of security defects or an
independent penetration test. The C analyzer does not analyze Swift; Swift
was reviewed manually and checked by its compiler and regression tests.

REPORTING
Use this repository's private vulnerability reporting feature for security
issues. Do not put passwords, tokens or personal data in a public issue.

CI
GitHub Actions repeats the core tests, C static analysis, sanitizer checks,
native build, local signature verification and full-history secret scan.
Checkout is pinned to a commit; the scanner download is checksum-pinned.
CI uses read-only repository permissions and needs no stored signing keys.
